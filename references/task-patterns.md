## 一、任务设计公式

```text
真实角色
  × 课程里刚教过的工具/方法
  × 一个具体输入（数据/文档/坏样例/需求）
  → 一个可交付成果
  → 交给一个具体对象使用
  → 用证据证明它可用
```

检查这个公式是否成立：

- 去掉「课程里教的方法」，任务还成立吗？如果还成立，说明任务和课程关系弱。
- 去掉「具体输入」，学员还能开始吗？如果只能从空白开始，任务太开放。
- 去掉「交付对象」，还有人用吗？如果只是交给老师，任务不像真工作。
- 去掉「证据」，还能判断做对了吗？如果不能，验收标准不够。

## 二、6 种任务原型

### A. 工具工作流型

**适用信号**：课程教了某个软件、CLI、平台、插件、自动化工具；内容里有明确操作步骤；工具能产出文件/表/链接。

**任务句式**：

> <角色>用<工具>，把「<手工流程，原耗时>」变成「<一句话/一条工作流，新耗时>」，交付<可复用的成果>。

**主交付物**：一张表、一份文档、一个可分享链接、一个脚本/命令记录。

**关键证据**：操作日志、前后对照、可复现的命令/步骤、关键数字核对。

**评分重点**：任务是否真的跑通；结果是否可复现；学员能否解释每一步在干什么；是否只复制粘贴。

**案例参照**：`微型PBL/AI办公/AI办公四工具微PBL选题.md`
- 飞书 CLI：5 条一句话消费 → 记账多维表 → 月度财报文档。
- Claude Code：脏 CSV → 清洗/透视 → 带图表的数据周报。

**常见失败**：把「工具介绍」当任务；步骤写了但没输入；产出是截图而不是可用文件；学员不会解释命令。

---

### B. 内容生产型

**适用信号**：课程教了写作、视频、图文、营销、教学设计；有内容标准、受众、发布渠道；课程里有正例/反例。

**任务句式**：

> 为<具体品牌/产品/受众>生产一套<内容形态>，用于<发布/投放/教学场景>，并说明<内容策略>。

**主交付物**：一套可直接使用的内容包（文案 + 配图/视频/分镜 + 发布说明）。

**关键证据**：发布版、修改前后对照、受众反馈/自评、素材来源与授权。

**评分重点**：是否对准目标受众；内容是否有明确策略；是否能发布；是否尊重版权与事实。

**案例参照**：`微型PBL/跨境电商AI产品宣传视频_样板微PBL_文图视频一条龙出片.md`
- 从产品资料到宣传视频，交付「脚本 + 画面 + 成片」。

**常见失败**：只写「创作一条文案」没有受众/渠道；交付物无法直接发布；用 AI 编造产品卖点；没有素材版权说明。

---

### C. 分析决策型

**适用信号**：课程教了指标、框架、分析方法、投研/运营/产品决策；有真实数据或案例；课程要求做判断而非计算。

**任务句式**：

> 用<分析框架/指标>分析<真实数据/案例>，回答<一个业务问题>，给<决策者>一份<建议/备忘录>。

**主交付物**：分析报告、决策备忘录、优先级清单、复盘文档。

**关键证据**：数据来源、计算过程、关键假设、结论与证据的对应关系。

**评分重点**：结论是否有数据支撑；是否区分事实/假设/建议；是否给出可执行动作；数字是否可复算。

**案例参照**：`Attachments/AI金融投研入门课_项目简介背景成果.md`、`NexAI能力体系/第1章_实战任务提交方案.md` 中的数据分析任务。

**常见失败**：报告很长但没有结论；数据与建议脱节；把 AI 生成的数字当真；没有说明口径。

---

### D. 系统搭建型

**适用信号**：课程教了 Prompt、RAG、Agent、工作流、低代码平台；有真实用户和场景；需要把多个部件装在一起。

**任务句式**：

> 为<具体用户>搭一个<最小系统>，解决<一件重复/要查资料/要判断的事>，并证明它在<测试用例>上可用。

**主交付物**：可运行原型（链接/文件）+ 设计卡（场景/用户/输入/输出/能力/知识源/工具/边界/验收）。

**关键证据**：测试记录（含陷阱题）、调用日志、知识源出处、边界说明。

**评分重点**：是否真跑通；回答/动作是否有依据；是否测过失败场景；边界是否清楚；是否越权。

**案例参照**：`微型PBL/企业级智能体/企业级智能体工作坊微PBL选题.md`
- 2 小时搭企业智能体：定题 → 搭骨架 → 接知识 → 加工具 → 试与磨；交付「智能体 + 设计卡 + 测试记录」。

**常见失败**：只搭「会聊天」的 Demo；知识库整本丢进去不测试；没有陷阱题；工具权限过大；把内部资料/凭证公开。

---

### E. 诊断优化型

**适用信号**：课程教了错误类型、评测、调试、Prompt 迭代、bad case 分析；有明确的好/坏标准；学员需要判断「哪里错、为什么错」。

**任务句式**：

> 给定一个<坏输出/低效流程/失败案例>，用<诊断框架>定位问题，修一版，并用<测试>证明修好了。

**主交付物**：修复后的版本 + 诊断说明 + 前后对照。

**关键证据**：原始失败样例、根因分析、修改点、复测结果。

**评分重点**：是否找到根因而不是改表面；是否只改必要的地方；修复是否可复现；有没有引入新问题。

**案例参照**：`NexAI能力体系/第1章_实战任务提交方案.md` 的 Prompt 迭代任务；AI 私教 v1 → v2 的测试迭代。

**常见失败**：一上来重写全部；只改措辞不解决根因；没有复测；把「模型随机性好」当万能借口。

---

### F. 拆解复刻型

**适用信号**：课程教了架构、开源项目、优秀案例、模板结构；目标是「看懂 → 能改」，不是只欣赏。

**任务句式**：

> 拆解<样板/开源项目>的<结构>，画出骨架，并复刻一个<最小版>，证明你理解了每个部件的作用。

**主交付物**：拆解报告/结构图 + 最小复刻件。

**关键证据**：结构图、部件职责说明、复刻件运行记录、出处标注。

**评分重点**：是否拆到部件级；是否能解释「为什么这样放」；复刻是否真跑通；是否标注来源、没有照抄。

**案例参照**：`微型PBL/AI家教/AI私教三课微PBL选题.md`
- 解剖 bloom-tutor → 复刻最小私教 v1 → 加自适应分支 + 测试 → v2。

**常见失败**：把「通读一遍」当拆解；复刻=复制原文；没有运行证据；不标出处。

## 三、内容 → 任务映射表

| 课程内容信号 | 优先原型 | 任务动作 | 主交付物 | 证据 |
|---|---|---|---|---|
| 工具操作步骤 / 平台演示 | A | 跑通一条真实工作流 | 文件/表/链接 | 操作记录、前后对照 |
| 写作/视频/设计方法 | B | 为真实对象生产内容 | 内容包 | 发布版、修改记录 |
| 指标/框架/案例判断 | C | 分析并给建议 | 报告/备忘录 | 数据来源、计算过程 |
| Prompt/RAG/Agent/工作流 | D | 搭最小系统 | 原型 + 设计卡 | 测试记录、日志 |
| 错误类型/评测/迭代 | E | 诊断并修复 | 修复版 + 说明 | 失败样例、复测 |
| 架构/开源/样板 | F | 拆解并复刻 | 拆解报告 + 复刻件 | 结构图、运行证据 |
| 纯概念/历史/原理 | C 或 E | 用概念做选型/诊断/方案对比 | 决策备忘录/诊断报告 | 论证链、案例对照 |

> 纯概念内容不要硬做「操作任务」；把「理解」转成「用这个概念做一个判断」，仍然可以是 PBL。

## 四、任务链的 4 种模式

### 1. 流水线型

```text
任务 A 产出 → 任务 B 的输入 → 任务 C 的输入 → capstone
```

适合：API → 封装 → Prompt → 系统；素材 → 脚本 → 视频 → 发布。

要求：每个产出都有明确格式，下一任务直接拿来用；不要让学员重新造一遍。

### 2. 分层搭建型

```text
定题 → 搭骨架 → 接知识 → 加工具 → 测边界
```

适合：Agent、RAG、工作流、产品原型。

要求：每层都能独立演示；最后用「测试记录」把各层串起来。

### 3. 拆解 → 复刻 → 打磨型

```text
看懂结构 → 复刻 MVP → 加分支/测试 → 上线版
```

适合：开源项目、Skill、模板、优秀案例。

要求：复刻不是抄；最后必须有「测试 → 改 → 再测」的痕迹。

### 4. 诊断循环型

```text
跑基线 → 找失败 → 修一处 → 复测 → 记录 → 再修
```

适合：Prompt 优化、数据分析、内容改写、流程提效。

要求：一次只改一个变量；记录「问题 → 原因 → 改法 → 结果」。

## 五、从旧作业改成 PBL 任务

用户给一个旧作业/题目时，按下面 5 步改造：

1. **加角色**：谁在做这件事？他的岗位目标是什么？
2. **加对象**：成果交给谁用？对方要拿它做什么决定/动作？
3. **加输入**：给真实数据/文档/坏样例，不要从空白开始。
4. **加判断**：至少让学员做一个取舍（选工具、定口径、排优先级、改哪一处）。
5. **加验收**：把「完成」改成 3–5 条可检查标准，并指定证据。

改造示例：

| 旧作业 | PBL 改造 |
|---|---|
| 「写一个客服 Prompt」 | 「给一个真实 FAQ 和 10 条用户问题，写客服 Prompt，让 3 个非技术同事试用，根据误答改一版，交付 Prompt + 测试记录」 |
| 「分析这份销售数据」 | 「运营主管要在周五会上决定下周主推区域；用这份脏数据做清洗和区域×周分析，交付 1 页决策备忘录 + 可复算的口径说明」 |
| 「总结第三章」 | 「用第三章框架诊断一个真实 bad case，指出根因并给修复方案，交付诊断报告 + 修复前后对照」 |

## 六、常见任务骨架

### 骨架 1：20 分钟微任务

```text
场景（2 min）→ 给输入 + 模板（3 min）→ 学员做 1 条最小工作流（10 min）
→ 对照验收自检（3 min）→ 交 1 个文件/链接（2 min）
```

### 骨架 2：45–90 分钟标准任务

```text
任务发布（5 min）→ 示范关键判断（10 min）→ 学员分 3 步做（45 min）
→ 测试/互评（10 min）→ 改一版（10 min）→ 提交（5 min）
```

### 骨架 3：多节课任务链

```text
capstone 定义 → 倒推 3–5 个中间交付物 → 每节课一个任务 → 每任务一个验收点
→ 最后一节课只做整合、测试、展示，不引入新知识
```

### 骨架 4：诊断型任务

```text
给 baseline + 失败样例 → 学员用检查清单定位 → 只改一处 → 复测
→ 记录前后差异 → 再改一处（可选）→ 交付修复版 + 迭代日志
```
