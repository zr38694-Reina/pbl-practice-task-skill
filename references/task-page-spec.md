# 实战任务页（HTML）生成规范

任务包（Markdown / Word）交付之后，把每个任务做成一页可直接发给学员的 HTML。
**先确认，再生成**：任务包交付后不要顺手出页面，先问清「哪些任务、几份、放哪」，等用户明确同意再动手——页面是任务卡的展示版，任务卡一变，页面全要重做。
**一任务一页**，页面是任务卡的「展示版」，不是新的教学设计——内容以任务卡为准，页面只负责让人一眼看懂「我要干什么、交什么」。

- 外壳模板：`assets/task-page-template.html`（复制后只换内容，不动样式与脚本）
- UI 体系：沿用 `learning-page-builder` 的**方块科技风**（白底黑墨 + 科技蓝 `#1a4be0`、无阴影无渐变、圆角只取 14/10/8 三档、单一色相靠明度分层）

---

## 1. 五块必备内容（缺一块就是不合格）

| # | 块 | 必须写什么 | 写法纪律 | 常见错误 |
|---|---|---|---|---|
| 1 | **任务名称** | 任务编号 + 名字 + 一句话任务 | 名字 ≤14 字、动词开头、不带黑话；一句话任务按「谁 用 AI 把 什么 变成 什么，交给谁用」 | 名字写成「第三章作业」；一句话任务写成「提升 AI 能力」这种不可观察的话 |
| 2 | **场景与对象** | 你是谁 / 你在帮谁 / 现在的问题 / 用在哪 | 四格写具体人、具体事、具体场合；「现在的问题」要有一句真实的卡点 | 写「假设你是某公司员工」这种空壳；交付对象写「交给老师」 |
| 3 | **任务目标** | 3 条可观察结果 | 每条以「能…」开头：能让 AI 产出什么 / 能判断什么 / 能修好什么；不写「理解 / 掌握 / 熟悉」 | 目标写成动作清单，和步骤重复；三条都是同一件事 |
| 4 | **步骤（流程图）** | 2 步，逐步写做什么 + 检查点 | 做成可点可播的流程图：节点文案 ≤14 字（动作），节点下写用时，点节点出详情卡 | 写成 5 步长清单；节点里塞整段说明；流程图画成装饰图不能点 |
| 5 | **常见错误** | 3 条，错误动作 → 正确做法 | 每条是学员真会犯的动作，配一句「为什么错」；不写「注意不要出错」 | 写成注意事项清单；三条都是同一类错 |

**不上页面的一块**：验收标准（维度 / 达标 / 优秀）只留在任务包的教师备注里。页面给学员看「要做什么」，验收表给讲师判分用，混在一页会让学员对着标准编答案、反而不敢动手。

**另外两块固定带上**（不属于五块但页面要有）：

- **AI 分工**：一行写清 AI 干什么、学员只干什么。没有这一行，学员会自己把活干完再让 AI 润色。
- **交付物 + 布置语**：一个交付物名称 + 提交格式（`docx` / `html` / `xlsx`），配「一键复制布置语」按钮。

## 2. 页面骨架（从上到下）

```
.topbar        品牌行 + 任务编号（不占屏）
.hero          任务名（H1）+ 一句话任务 + meta chips（用时 / 难度 / 交付格式 / 原型）
.sec 场景与对象   四格信息卡 + 「AI 分工」两栏
.sec 任务目标     3 条带编号方块的目标
.sec 步骤         流程图（2 节点，可点可播）+ 步骤详情卡
.sec 常见错误     错误 → 正确 对照卡
.sec 交付物       交付物名 + 布置语代码块 + 复制按钮
.foot          一句「教学示意」声明
```

顺序不要调：学员打开页面先要知道「这活是什么」，再知道「交给谁」，最后才看「怎么做、别踩哪些坑」。

**五个大标题固定用块名，一个字都不改**：`场景与对象` / `任务目标` / `步骤` / `常见错误` / `交付物`。不要改写成「这件事，落在谁身上」「做完你能做到这三件」「两步走完」「三个最容易踩的坑」这类文案化标题——学员扫一眼标题就知道这页有哪几块，比标题好看重要。要表达态度就写进标题下面那句小字（`.sec-note`）或卡片里，标题保持素。

---

## 3. 步骤用流程图呈现

两条硬要求：**必须是流程图**（有节点、有方向、有先后），**必须能点**（点节点看该步详情）。

- 节点 2 个，横向排列；窄屏（≤720px）自动转竖排，箭头跟着转向下。
- 每个节点只有三层信息：序号（01/02）→ 动作名（≤14 字）→ 用时（12 min）。
- 节点下方是一块详情卡：做什么 / 检查点 / 用小提示（「这一步必须留下什么」），点哪个节点切哪张卡。
- 顶部一个「▶ 播放步骤」按钮：按顺序点亮节点并自动切详情卡，播完变「↻ 再看一遍」。
- 节点是 `<button>`，键盘可聚焦；`prefers-reduced-motion` 下不播动画，直接显示全部节点。

不要做：把流程图画成一张静态图片（改文案要重画）；节点里塞 50 字说明（读不完）；三步以上还硬塞在一行（该拆任务了）。

## 4. UI 规范（继承 learning-page-builder）

| 项 | 取值 |
|---|---|
| 主色 | `--accent:#1a4be0`，配 `--accent-rgb:26,75,224`；暗色下 `#5b7cff` |
| 底色 | `--bg:#ffffff`、卡面 `--card:#ffffff`、浅底 `--surface:#f4f4f4` |
| 文字 | 正文 `#111111`、次要 `#6b6b6b`；暗色反转 |
| 分隔线 | `1.5px` 实线 `--hairline:#e6e6e6`，不用阴影 |
| 圆角 | 只取 14 / 10 / 8 三档（外大内小） |
| 字号 | 标题 `clamp(26px,3.2vw,44px)`、正文 17px、卡内正文 16px、注解 13px |
| 字体 | 系统栈（PingFang SC / Microsoft YaHei / Segoe UI），不引外部字体 |
| 形状 | 全页只有方块：无渐变、无阴影、无描边发光 |
| 装饰 | 允许一枚 2px 蓝竖线、一个蓝底方块编号；不要图标库、不要 emoji 堆叠 |

**不要做**：

- 不引外链（字体、图标、图片、CDN 一律不引），页面要能离线双击打开。
- 品牌 logo 用 **base64 data URI 内嵌**（`{{LOGO}}`，黑字版配白底，显示高度 24px）；源文件大就先缩到 480px 宽再转 base64，别把原图直接塞进去。
- 不放页内跳转链接到别的页面（会失效），续看靠文件名页序。
- 不写评分权重、不写验收表、不写教师备注、不写「本页学习目标」这类元说明。

## 5. 文案纪律

1. **从任务卡抄，不重写**：任务名、目标、常见错误都与任务卡逐字对得上；页面里改了，任务包要同步改。验收标准不上页面（留在任务包）。
2. **一页只讲一个任务**：出现「任务 2 也可以……」就说明该分页。
3. **称呼用「你」**：页面是发给学员的，不是发给讲师的。
4. **数字写具体**：12 min、3 条、2 步；不写「若干」「适当」。
5. **每块首句给结论**：场景块第一句说清「下班前要发三样东西」，不要从背景铺垫开始。

---

## 6. 交付前自检

- [ ] 五个大标题逐字等于块名（场景与对象 / 任务目标 / 步骤 / 常见错误 / 交付物），没有改写成花名。
- [ ] 五块齐全，顺序正确；AI 分工与交付物两块也在；页面里没有验收表。
- [ ] 步骤是 2 个节点、2 步详情；点节点能切、播放按钮能跑完、播完能重播。
- [ ] `grep '{{'` 无残留（模板占位符全部填完）。
- [ ] 内联 `<script>` 抽出来 `node --check` 全过。
- [ ] 320px 与 1280px 两档无横向溢出；流程图在窄屏是竖排。
- [ ] `prefers-reduced-motion` 下无动画，节点直接全亮。
- [ ] 全页无 `<a href`、无外链资源、无 emoji 图标。
- [ ] 点「复制布置语」，状态文字出现「已复制」（`file://` 下可能降级为提示手动复制，属正常）。
- [ ] 文件名符合 `任务页-NN-任务名.html`，与任务编号一致。

---

## 7. 命名与放置

```text
<课程目录>/任务页html/
├── 任务页-01-用AI干完三件文字活.html
├── 任务页-02-给AI做三个小实验.html
└── ...
```

- 文件名用任务编号 + 任务名，中文名不改、不加版本号；改动直接覆盖同名文件。
- 一次生成多个：先按任务顺序排好名，再一次写完，别边写边改编号。
- 交付时同时给出：页面文件路径 + 「每个页面哪块最容易被跳过」的一句提示 + 是否需要同步回任务包 md/docx。
