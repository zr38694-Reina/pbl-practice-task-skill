# PBL 实战任务设计 Skill

根据已有课程内容（大纲、讲义、字幕、PPT、课程概要、知识点清单）设计可直接布置给学员的 PBL 实战任务。

## 设计原则（硬规矩）

1. **AI 是主干**：把 AI 从流程里抽掉，任务就做不完（不只是变慢）。人只做三件事——给输入和标准、核结论、补现场信息。
2. **先判能力再出题**：先看课程里的「实操」在练哪种 AI 能力（C1 让 AI 干活 / C2 理解机制 / C3 信息处理 / C4 调研选型 / C5 提问拆解 / C6 沉淀复用 / C7 流程编排 / C8 判断与验证），任务的核心动作必须正面考这一个。
3. **最多 2 步**：第 1 步让 AI 跑出一版，第 2 步核一遍改一版交出去。真做不完就拆成两个任务，不加步骤。
4. **任务名说人话**：动词开头、≤14 字，不造黑话、不加「赋能/重塑/智能」这类词。
5. **提交格式写后缀**：布置语统一是「任务：…；请提交 docx 格式的…。」——写 `docx`，不写「文档格式」。
6. **搭建类先给 HTML 原型**：凡是「搭一个产品/工具/页面」，交付一个双击能开的单文件 `.html`（有交互、有假数据），不要上环境工程。

## 适用场景

- 根据一节课 / 一章内容出实战任务、课后作业、课堂练习
- 把一门课拆成 3–6 个递进任务，最后拼成一个 capstone
- 把旧作业改造成「有真实场景、有交付物、有验收」的 PBL 任务
- 给已有课程补任务卡、评分量规、脚手架和安全边界

## 它产出什么

默认输出一份 Markdown 任务包：

1. 设计摘要
2. 课程内容 → 任务映射
3. 任务总览（单任务或任务链）
4. 学员任务卡
5. 教师备注（时间、脚手架、评分、常见错误、安全边界）
6. 质量自检

**下一步**：任务包确认后，可把每个任务做成一页自包含的**实战任务 HTML 页面**（一任务一页，含任务名、场景对象、目标、流程图步骤、验收标准、常见错误，配一键复制布置语）——说「出任务页」即可，规范见 `references/task-page-spec.md`。

单任务标准版通常 150–250 行；不会默认生成巨型附件包。

## 用法

```text
/pbl-task 根据 Attachments/xxx课程概要.md，给零基础学员出一个 30 分钟课后实战任务，交付要能直接发给学员。
```

也可以直接说：

```text
帮我把这三节课设计成一条递进任务链，每个任务一个主交付物，前一个产出要被后一个使用。
```

## 设计依据

任务设计规律提炼自现有 PBL 课程资产：

- `微型PBL/AI办公/AI办公四工具微PBL选题.md`：单任务 · 单交付物 · 一条最小工作流
- `微型PBL/企业级智能体/企业级智能体工作坊微PBL选题.md`：搭 + 测，交付「能干活且能干对」的系统
- `微型PBL/AI家教/AI私教三课微PBL选题.md`：拆解 → 复刻 → 打磨
- `NexAI能力体系/第1章_实战任务提交方案.md`：前序产出 = 后序输入的证据链

## 不适用

- 从零设计整套课程大纲 / 选题 → 用 `micro-pbl-course-outline`
- 只出选择题 / 测验 → 用 `subtitle-processing` 的出题流程
